# Physical AI最終課題：実画像学習とリスク適応巡回の体系的文献レビュー

2026-10-16 調査・実装対応版。研究の紹介と、今回の実装内容は明確に分離する。

## 1. 研究課題からアーキテクチャへ

**問い**：非構造化環境の視覚的なインフラ問題をAIが分類した結果に基づいて、移動ロボットが点検の順序と走行速度を変えることは、距離優先巡回に比べて合理的か。

| 層 | 本課題で採用 | 文献上の位置付け | 不確実性 |
|---|---|---|---|
| データ取得 | HFに置かれた道路異常写真、revision固定 | データ中心の開発、再現性 | 収録偏り、類似画像、派生データの権利 |
| 画像認識 | ImageNet事前学習＋MobileNetV3-Smallの転移学習 | Efficient CNN / hardware-aware model | 分類対象は問題**種別**であってseverityではない |
| 不確実性対応 | validation温度スケーリング | 出力確率の過信を緩和する簡易較正 | OODに対する校正保証なし |
| リスク写像 | カテゴリ別の業務ルールで定める重み | Decision-aware planning / cost-sensitive action | 重大度の正解はない。重みは経験則 |
| 次の点検先 | scoreと距離の重み付き優先順位、A*経路 | Orienteering / informative path planningの簡易近似 | 厳密最適化でない |
| 速度 | 保守的上限ルール。PPOは1Dサロゲートで学習 | Rule-based safety layer / PPO | 物理安全の証明ではない |
| 実世界行動 | Genesis差動二輪車輪の関節速度制御、剛体位置フィードバック | Robotics control / physics simulation | ColabでのGPU/EGL動作未確認。実機検証なし |
| 評価・運用 | 固定seed、train/val/test、分類Macro-F1と物理指標を分離 | MLOps、RobOps、System Engineering | Data leakageとSim-to-Real gap |

### 講義資料との対応

- **第1回 MLOps・RobOps**：「モデル精度だけではなく、データ取得 → 学習 → 評価 → 配備 → 運用 → 再学習」、ロボット機構、ソフト・データを含むシステム設計。設計では`dataset_audit.csv`、`training_history.csv`、Genesisの物理trace、診断用Notebook00に分離した。
- **第6回 Open Source in Robotics**：OSS/モデル・データライセンスの区別、再現性、GitHub公開の必要性。HFのデータカードに記載されていても再配布時は元コンテンツの権利を確認。
- **過去の巡回ロボットNotebook**：合成温度・振動センサでのIsolation ForestとA*による巡回のBaselineを新しい実画像分類レイヤーに置き換え。ただしこれらは混在するタスクであり、旧2D数値を新3D数値として引用しない。

### Dataset leakage / ラベルバイアス

道路異常データはRoboflow由来を含む。画像拡張された同一画像の別サンプルが訓練と評価に分かれると、本来より高い分類指標が出得る。Notebook04では層化分割と固定乱数種に留めたため、重大な研究成果として報告する前に、画像のpHash近傍検索→類似画像グループ単位でのsplit、あるいは収録元単位の外部検証が必要。

また7カテゴリは問題の種類だけであり、「異常／正常」の二値分類と一般的な重症度回帰を同時に主張できない。分類confidenceは重大度の確率とは異なるため、`road_ml.RISK_BY_LABEL`は説明可能な仮説的重みとして保持。

## 3. 研究・技術文献と具体的採用

### A. Road damage dataset / Road computer vision

- Arya et al., *RDD2022: A multi-national image dataset for automatic road damage detection* (2022), https://arxiv.org/abs/2209.08538 . 道路損傷をD00/D10/D20/D40などで検出・位置特定するタスク設計の根拠。現Notebookの問題分類は物体検出ではないため、同じmAP指標を使わない。
- Jiang, *Road damage detection and classification using deep neural networks* (2024), https://link.springer.com/article/10.1007/s42452-024-06129-0 . YOLOv8を改良した小型路面損傷検出の比較研究。今後の位置推定版で参照。

### B. MobileNetV3（採用）

- Howard et al., *Searching for MobileNetV3*, ICCV 2019, https://openaccess.thecvf.com/content_ICCV_2019/html/Howard_Searching_for_MobileNetV3_ICCV_2019_paper.html . 軽量CNNをハードウェア制約込みで探索。Colabで小規模に転移学習し、ローバー側で推論する設計に合う。Notebook04はSmallの分類層をfine-tune。https://docs.pytorch.org/vision/master/models/generated/torchvision.models.mobilenet_v3_small.html
- HF image classification実装ガイド：https://huggingface.co/docs/transformers/tasks/image_classification . データ読み込み、事前学習モデル、augmentation、学習・評価のパイプライン。Notebook04ではtorchvisionベースで簡略化。

### C. PPO（追加発展・任意）

- Schulman et al., *Proximal Policy Optimization Algorithms*, 2017, https://arxiv.org/abs/1707.06347 . 安定化されたpolicy-gradient更新。Notebook05はGymnasiumのオリジナル1D速度環境にStable-Baselines3 PPOを適用。**Genesis物理を使う強化学習とは異なる**。
- Stable-Baselines3 official custom env：https://stable-baselines3.readthedocs.io/en/master/guide/custom_env.html . `reset(seed)`, `step(action)`, 観測・行動空間、`check_env`の契約を採用。
- PPOの実装詳細・再現性：https://iclr-blog-track.github.io/2022/03/25/ppo-implementation-details/ . 学習安定化、実験条件のログに関する参考。

### D. 代替工場異常検知：PatchCore（現Notebookでは未実装）

- Roth et al., *Towards Total Recall in Industrial Anomaly Detection*, CVPR 2022, https://openaccess.thecvf.com/content/CVPR2022/html/Roth_Towards_Total_Recall_in_Industrial_Anomaly_Detection_CVPR_2022_paper.html . 正常だけで学習し、パッチ特徴メモリバンクで欠陥を同定する方法。MVTec ADを活用して旧案の工場点検へ戻す場合、Isolation Forestからの発展として最優先候補。
- 技術実装例: https://github.com/amazon-research/patchcore-inspection . 研究実装の構造を学ぶ参考。ソースを提出物へ転用する場合はライセンスと引用を確認する。

### E. Sim-to-Real（今回の制約）

- Tobin et al., *Domain Randomization for Transferring Deep Neural Networks from Simulation to the Real World*, IROS 2017, https://doi.org/10.1109/IROS.2017.8202133 . 画像の質感や照明条件などをランダム化してReality Gapを減らす研究。今回は**Genesisカメラ映像と実画像の統一学習を行っていない**ので、Domain Randomizationを採用済みと表現しない。
- Genesis公式Camera/Rendering：https://genesis-world.readthedocs.io/en/latest/user_guide/rendering/index.html 及び https://genesis-world.readthedocs.io/en/latest/api_reference/visualization/camera.html 。Headless描画、カメラ記録。Colab OpenGL互換性を実機で検査する。

## 4. 発展提案の順位と加点への貢献

1. **必須（まず成立させる）**：HFデータ→MobileNetV3学習（Macro-F1）→画像種別からのリスク順位→Genesis3D車輪制御→90s動画。学習モデルが実際の行動を変えることを検証。
2. **強化（性能比較）**：NearestとAdaptiveで同じ画像・同じ環境を実行。走行距離、重大カテゴリの初回訪問時刻、完了設備数をペア比較。類似度をもとにリスク推定が不確実な場合はhuman review。
3. **追加発展**：PPO速度政策と安全シールド。1D環境とGenesis実走行を分けて評価し、単なるPPO導入自体を成果としない。
4. **将来的な研究**：HF道路写真をGenesisマテリアルへ適切にマッピングし、オンボードカメラで直接推論。カメラ観測の画角・遮蔽・距離で認識率が変わる。Domain Randomization / Sim-to-Real比較。現パッケージでは未実装。

## 5. レポートで使う表現例

> 本研究では道路インフラ問題の実画像データでMobileNetV3-Smallを転移学習し、問題カテゴリの予測結果を明示的なリスク優先規則へ変換した。リスクと巡回距離に応じた行動選択をGenesis 3D剛体物理シミュレータ上の差動二輪ロボットで検証した。画像入力はシミュレータ内蔵カメラではなく、データセット由来の外部仮想点検カメラとして実装した。カテゴリ分類性能とロボットの巡回タスク指標を分けて評価した。

**してはいけない主張**：実際の公道で自動運転した、Genesisカメラ画像から道路の穴を検出した、危険確率を学習した、Genesis物理上で強化学習済み、AIによる安全保証をした、等。
